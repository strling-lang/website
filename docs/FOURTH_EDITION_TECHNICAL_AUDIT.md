# STRling 4.0.3 website technical audit

## Baseline and method

The latest public compiler release checked on November 19, 2026 was [STRling 4.0.3](https://github.com/strling-lang/strling/releases/tag/v4.0.3). Its tag points to certified source `d01ac3785736ad552c90f00b4ca13c0e2e5c9c62`. The accepted certification closure is `eba5dad3de3fa620eb1ea13e0514d02f4b23e288`. The public release and later distribution verification are linked separately on the website's Project page. Website implementation started at `7534e38` on `dev`.

- The [authority hierarchy](https://github.com/strling-lang/strling/blob/d01ac3785736ad552c90f00b4ca13c0e2e5c9c62/governance/authority.md), architecture decision, and [specification hub](https://github.com/strling-lang/strling/blob/d01ac3785736ad552c90f00b4ca13c0e2e5c9c62/spec/README.md) govern interpretation. The Semantic Specification is unratified. The two textual dialects and Simply protocols are normative for their declared versions and scopes.
- The certified tree's compiler and binding sources, frontend grammar and fixtures, canonical data contracts, interop ABI and transport contracts, conversion and explanation models, target profiles, portability registry, stdlib registry, and relevant test fixtures supplied implementation and contract evidence. The shipping npm artifact supplied runnable compiler evidence. The website tests used Node 22.12.0 and ECMAScript 2024 profile 1.3.0. These are observations for the example environment. Upstream TypeScript runtime status remains Preview.
- The generic RegEx catalog is a projection of the [pinned Regex Conformance snapshot](https://github.com/strling-lang/regex-conformance/blob/3285cc9fa8310df0af00fa50724d65531e0695d9/semantic-corpus/snapshots/regex-semantic-features-2026-09-08.v4.json). The technical audit separates corpus definitions, source manifestations, certified runtime observations, and STRling target lowering.

## Example evidence and limits

- The audit test extracts and executes ten current reference/From RegEx fragments, two page comparisons, three full Advanced article runners, and a Semantic STRling example with a failing parse control. It also checks a recorded Simply 1.1 repeat and runtime behavior. The setup fragment uses the same imports and checked-in profile as the tests.
- Existing fixture tests exercise the downloadable Advanced and Frontier implementations. Partial application excerpts are explained in their lesson context and checked through the complete modules and fixtures. Model grammar, input fixtures, and generic corpus test concepts are reference data rather than standalone programs.
- The legacy quickstart ran four TypeScript fences and one Python fence with their pinned packages. The legacy tour ran twelve TypeScript fences. The quickstart's displayed historical RegEx is labeled as a shape.
- Exact artifact and match observations here apply to ECMAScript for the exercised inputs and runtime. PCRE2 and Python current-target claims were reviewed through the pinned profiles and support evidence. This audit did not independently recertify every binding, execute third-party catalog manifestations, or regenerate the canonical feature corpus.
- No product release, immutable compiler evidence, registry packages, production checkpoint, or deployment was modified.

## Validation and deployment gate

**READY FOR DEPLOYMENT.** The confirmed website-level discrepancies were corrected and the scoped contract, example, and rendered checks passed. The generic corpus and gated production tools retain their existing evidence boundaries.

- Astro check and ESLint passed. The final production build generated 332 HTML pages.
- The full website test command passed 93 unit tests and the internal link check. This included the optional hash check of the pinned upstream release policy.
- The independent source-lock check passed against the canonical Regex Conformance checkout. Its rendered route gate confirmed all 16 categories and 269 features. A separate HTML inventory found one primary heading, title, canonical link, and nonempty description on each of the 332 built pages.
- Targeted desktop and mobile Playwright coverage passed 78 checks, with two project-specific skips. The selection covered authored routes, package presentation, gated Lab states, all catalog routes, lesson classification and navigation, and discovery artifacts.
- Changed-file formatting passed. The repository-wide formatting check still flags 77 unchanged files in this checkout. No broad formatting cleanup was applied.
- The final audit changes are local. Normal website review and deployment authorization still apply.
